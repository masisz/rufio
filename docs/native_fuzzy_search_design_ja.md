# 内蔵曖昧検索の設計（rufio 1.6.0）

ブランチ: `v1.6.0`
ステータス: Phase 1〜3 実装済み。再表示キャッシュとプレビューは Phase 4 で行う。

## 目的

外部 fzf に依存せず、ファイル名・パスを順序を保った飛び飛び一致で検索する。
絞り込み速度は fzf と同等以上、再表示は候補キャッシュによる短縮を目指す。
現時点では性能目標であり、Zig 化だけで高速化を保証しない。

## 責務

- Zig: 候補を保持し、照合・スコア計算・上位 K 件の選別を行う。
- Ruby: 入力、検索世代の管理、Screen / Renderer による表示、選択後の操作。
- Ruby フォールバック: 同じ検索仕様を持ち、ライブラリがない・古い場合にも利用できる。
- 既存 `core_files_create` を候補列挙に利用し、入力ごとに走査し直さない。

## 検索仕様（Phase 1）

- UTF-8 のコードポイント単位の部分列一致。ASCII の英字だけ大文字小文字を無視する。
  日本語はそのまま照合する。Unicode 正規化・非 ASCII の case folding は初期対象外。
- 1 文字の一致 +16、パスの最後の区切り以降 +8、単語境界 +8、連続一致 +24。
  先頭からの距離と一致間の隙間は 1 文字につき -1、候補の文字数を減点し、全体一致は +64。
  境界は先頭、`/`・`\\`・`_`・`-`・`.`・空白の直後、小文字から ASCII 大文字への遷移。
- 動的計画法で最も高いスコアの一致を選ぶ。同スコアでは末尾の一致位置が早い方を選び、
  同一末尾への遷移が同点なら直前の一致位置が早い方を選ぶ。
- 候補の順位はスコア降順、同点は追加時の ID 順。空クエリでは追加順。
- 位置は元の UTF-8 文字の先頭バイトオフセットとして返す。描画時に表示幅へ変換する。
- 候補は追加後に保持し、再検索で再転送しない。上位 K 件だけを返し、総一致件数は別に保持する。
- 不正 UTF-8 / NUL を含む文字列は明示的に拒否する。クエリは 1,024 バイト、
  候補は 65,536 バイト、返却件数は 10,000 件を上限とする。
  ファイル走査側は表示用文字列を scrub し、実際に開くパスは別に保持する。

## FFI と寿命

`core_fuzzy_create` / `add` / `query` / `results` / `destroy` を独立した API 群として追加する。
候補は NUL 区切りの UTF-8 でまとめて追加し、ID は 0 からの追加順とする。
結果は little-endian のバイナリで、先頭に総一致件数 u64 と返却件数 u32、
各レコードに ID u64、スコア i64、一致位置数 u32、位置 u32 配列を格納する。
結果ポインタは次の query / destroy まで有効。Ruby はその場でコピーする。
同じハンドルへの呼び出しは直列化し、close は冪等にする。古いライブラリの関数不足は
他の検索・ZIP API の利用可否に影響させない。

候補ごとの FFI 呼び出しと全件ソートを避け、Zig では最悪候補を根にしたヒープで
上位 K 件を保持する。スコアは O(候補文字数 × クエリ文字数)、作業領域は O(候補文字数)。
一致位置の復元用 O(候補文字数 × クエリ文字数) の領域は上位候補にのみ、一候補ずつ確保する。
スコア計算前に部分列として成立するかを O(候補文字数) で確認し、不一致を早期除外する。

## 実装段階

1. **検索コア**: Zig / Ruby 共通仕様、永続候補、top-K、一致位置、FFI、比較テスト、ベンチマーク。
2. **検索セッション（実装済み）**: 非同期走査、入力の集約、世代番号による古い結果破棄、キャンセル。
   単一の検索ワーカーでインデックスのハンドルを専有し、UI スレッドから destroy しない。
   走査は別のプロデューサーで実行し、受け渡しには容量制限を設ける。
   実測で長い query が問題なら、スコア走査中のキャンセルを追加する。
3. **操作の置き換え**: `s` / `/` を内蔵画面へ、`F` の rga 結果選択も共通画面へ接続する。
   `F` の本文検索には引き続き rga を使う。fzf のヘルスチェックと説明を除去する。
   既存の `fzf_search` アクション名はユーザー設定互換のため別名として維持する。
4. **再表示とプレビュー**: キャッシュを容量・有効期限で制限し、再走査による更新を可能にする。
   新規・削除・外部更新を考慮し、キャッシュ結果が常に最新とは表示しない。
   選択後のプレビューは非同期・サイズ制限付きとし、結果到着で選択 ID が動かないようにする。
5. **展開**: G のファイル名検索と f のフィルターへ適用を検討し、8 プラットフォームをビルド・検証する。

`s` の現行 find は隠しファイルを含む。G の除外拡張子を無条件に流用しない。
ディレクトリのシンボリックリンクは追わない。内蔵候補一覧では通常ファイルへのリンクも含める
（現行 `find . -type f` からの変更点）。Ruby / Zig の一覧で同じ扱いになることをテストする。
本文検索そのものの高速化と、fzf の検索式全体の互換性は本計画の対象外。

## 検証と計測

- 期待する順位・一致位置、日本語・空文字・重複・同点・追加後の再検索・解放をテストする。
- 同じ候補とクエリで Ruby / Zig の ID・スコア・位置・総件数を一致させる。
- Debug ビルドで安全性を検証し、速度は ReleaseFast で測る。
- 1 万・10 万・100 万候補を用意し、登録時間、検索中央値・p95、返却上限、メモリを測る。
- fzf 比較では同一候補入力を使い、起動・入力転送込みの時間と検索コア時間を区別する。
  初回ディスク走査、入力から描画まで、再表示、プレビューは UI 実装後に別途測る。
- ベンチマークは通常の単体テストから分離し、測定環境・件数・クエリ・試行数を記録する。

## Phase 2 の成果（2026-11-14）

### 非同期セッション

`Rufio::FuzzySearchSession` を追加した。1 回の検索画面に 1 セッションを割り当てる。
再利用するインデックスはセッション内だけで、画面の再表示キャッシュは Phase 4 の対象。

- `start` で走査と検索の 2 ワーカーを開始する。検索インデックスは検索ワーカー内で
  作成し、追加・照合・解放もそのワーカーだけで行う。
- `update_query` は最新の入力と世代番号を保存してすぐ戻る。実行中の検索が戻ったら
  中間の入力を飛ばして最新の入力を処理する。検索中に別の native query を重ねない。
- 世代の古い結果は公開時と `poll` 時に破棄する。入力変更時点で表示済み結果も消し、
  前の検索の結果を選択しないようにする。
- `poll` は最新のスナップショットを最大 1 個取り込む。`snapshot` は凍結済みで、
  クエリ・結果・総一致件数・登録件数・進行状態・エラーを同じ版として読める。
  結果は `{ id:, score:, positions:, entry: }`、entry は表示名 `text` と元の `path` 等を持つ。
- 走査から受け取る待機キューは最大 4 バッチ × 256 件。キューが満杯なら走査側を待たせる。
  検索ワーカーは一度に最大 4 バッチを取り込み、件数に比例して待機キューが膨らまない。
  インデックス本体とパスの登録件数にはまだ上限を設けていない。
- 候補追加だけで起きる再検索は既定で 50ms 間隔に集約する。入力変更と走査完了は
  この待ち時間を省く。ただし実行中の照合は完了を待つ。走査が一時停止していても
  待機期限で起きて部分結果を更新する。`refresh_interval` で間隔を変更できる。
- `scanning?` は未登録の候補バッチも含む。`searching?` は現在の入力・登録候補に
  対する結果更新の待機中も true になる。候補追加の集約中は、同じクエリの一つ前の
  部分結果を保持するため、総一致件数はまだ増え切っていないことがある。
- 走査エラーは最大 100 件保持し、読めたファイルの検索は続ける。
  検索ワーカーが失敗した場合は走査側も停止し、エラーを公開する。

### ファイル一覧

`Rufio::FuzzyFileSource` は既存の `core_files_create` を使い、未搭載・
`RUFIO_NATIVE_SEARCH=0`・`native: false` の場合は Ruby で走査する。
隠しファイルを含め、G モードの除外拡張子は持ち込まない。ファイル本文は開かない。
ディレクトリのリンクと壊れたリンクは候補にせず、通常ファイルへのリンクは含める。
表示名だけを UTF-8 に scrub し、元のパスは元のバイト列・エンコーディングのまま保持する。

`source:` に独自プロデューサーを渡すこともできる。実装する契約は
`each_batch(cancelled:, on_error:) { |batch| ... }`。
バッチの各項目は文字列、または `{ text: '表示名', path: '元のパス', line_number: 4 }` のような
Hash とする。メタデータの値は文字列・数値・Symbol・真偽値・nil に限り、文字列はコピーして
保持する。これにより Phase 3 の rga 結果選択にも同じセッションを利用できる。

### 終了と制約

`close` は停止通知を送り、待機キューと公開結果を破棄して戻る。
UI スレッドでは join・destroy・`Thread#kill` を呼ばない。
進行中の FFI 呼び出しやファイルシステム操作が戻った後、所有ワーカーが解放する。
ネイティブ走査は空バッチで待っている間も停止通知を確認できるよう、
`NativeContentSearch#each_batch(cancelled:)` に省略可能な停止判定を追加した。

アプリ終了等で完了を待つ場合は、`close` の後に `wait(timeout: 秒数)` を呼ぶ。
false は解放処理がまだ継続中であることを示す。`wait` 自体は停止要求ではなく、
close 前に呼ぶと次の入力を待つ検索ワーカーも待ち続ける。
独自 source はバッチ間で停止判定を確認する必要があり、ブロックした任意の I/O を
強制終了する仕組みは設けていない。照合途中の Zig キャンセルもまだ追加していない。

```ruby
session = Rufio::FuzzySearchSession.new(root: Dir.pwd).start
begin
  session.update_query('sctrl')
  loop do
    session.poll
    state = session.snapshot
    # 描画・選択処理には state.results と state.errors を渡す。
    break unless state.scanning || state.searching

    sleep 0.01
  end
ensure
  session.close
  session.wait(timeout: 1) # false の場合、所有ワーカーでの後処理は継続する。
end
```

## Phase 3 の成果（2026-11-15）

### 画面とキー

- `Rufio::FuzzyFinder` を追加した。G mode と同じく全画面で描画し、`TerminalUI#start_fuzzy_finder(session, title:) { |entry| ... }`
  で開く。1 回の表示に 1 つの `FuzzySearchSession` を割り当て、開くときに start、ESC・選択・G mode の起動で close する。
- 入力は G mode の矢印・SS3・CSI u の解釈を共有する（`TerminalUI#search_overlay_active?`）。
  文字キーはすべて検索語になり、`?` もヘルプではなく入力として扱う。Ctrl+J は `"\n"` と同じバイトなので Enter には使わない。
- 一致位置（UTF-8 先頭バイトオフセット）を表示桁へ変換してハイライトする。省略記号で切った行は省略記号を上書きしない。
- 候補の追加で順位が変わっても、選択中の候補 ID を追う。検索語を変えたときは先頭に戻す。
- 選択時のコールバックが `:needs_refresh` を返すと全画面を再描画する（外部エディタから戻った後）。
- 全画面ビューで結果が減ったときに前フレームの行が残る不具合があった（G mode も同じ）。
  `Screen#clear(mark_dirty: true)` で全行を Renderer の比較対象にして解消した。既定の `clear` の動作は変えていない。

### 操作の置き換え

- `s` / `/`: `SearchController#file_search` が現在のディレクトリを `FuzzyFileSource` で列挙する。
  選択したファイルは従来どおり `FileOpener#open_file` で開く。
- `F`: 入力ダイアログで検索語を受け取り、`RgaResultSource` が `rga --line-number --with-filename --no-heading --color never -- 語 .`
  の出力を 256 件ずつ流す。表示名は scrub し、パスは元のバイト列から組み立てる。
  停止判定は 50ms ごとに確認し、出力が止まった rga も終了させてから回収する。選択行は `open_file_with_line` で開く。
- アクション名を `file_search` / `file_search_alt` に変更した。ユーザー設定の `fzf_search` / `fzf_search_alt` は別名として
  受け付け、新しい名前と両方ある場合は新しい名前を優先する（`ConfigLoader::LEGACY_KEYBIND_ACTIONS`）。
- ヘルスチェックから fzf を除いた。プレビューは Phase 4 で追加するため、fzf の `--preview` 相当はまだない。

### 同梱バイナリと計測

`rake native:build` で全 8 プラットフォームを再ビルドし、`rake native:check` と `make test`（Zig 単体テスト）を通した。
これで通常起動でも `FuzzySearch#native?` が true になる。全 1,456 テスト、失敗・エラーなし（7 件スキップ）。

手元の macOS（Darwin 27.2）・arm64・同梱の ReleaseFast ライブラリで `~/devs` 配下 168,432 ファイルを `FuzzyFinder` で開いた一回の測定では、
走査と登録の完了まで 1,134ms、その後の `sctrl` の結果取得まで 59ms（総一致 41,493 件）だった。
キー入力から描画までの時間はまだ計測していない。
