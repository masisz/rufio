# 内蔵曖昧検索の設計（rufio 1.6.0）

ブランチ: `v1.6.0`
ステータス: Phase 1 実装済み。外部 fzf の置き換えは Phase 3 で行う。

## 目的

外部 fzf に依存せず、ファイル名・パスを順序を保った飛び飛び一致で検索する。
絞り込み速度は fzf と同等以上、再表示は候補キャッシュによる短縮を目指す。
現時点では性能目標であり、Zig 化だけで高速化を保証しない。

## 責務

- Zig: 候補を保持し、照合・スコア計算・上位 K 件の選別を行う。
- Ruby: 入力、検索世代の管理、Screen / Renderer による表示、選択後の操作。
- Ruby フォールバック: 同じ検索仕様を持ち、ライブラリがない・古い場合にも利用できる。
- 既存 `core_files_create` を候補列挙に利用し、入力ごとに走査し直さない。

## 検索仕様（Phase 1）

- UTF-8 のコードポイント単位の部分列一致。ASCII の英字だけ大文字小文字を無視する。
  日本語はそのまま照合する。Unicode 正規化・非 ASCII の case folding は初期対象外。
- 1 文字の一致 +16、パスの最後の区切り以降 +8、単語境界 +8、連続一致 +24。
  先頭からの距離と一致間の隙間は 1 文字につき -1、候補の文字数を減点し、全体一致は +64。
  境界は先頭、`/`・`\\`・`_`・`-`・`.`・空白の直後、小文字から ASCII 大文字への遷移。
- 動的計画法で最も高いスコアの一致を選ぶ。同スコアでは末尾の一致位置が早い方を選び、
  同一末尾への遷移が同点なら直前の一致位置が早い方を選ぶ。
- 候補の順位はスコア降順、同点は追加時の ID 順。空クエリでは追加順。
- 位置は元の UTF-8 文字の先頭バイトオフセットとして返す。描画時に表示幅へ変換する。
- 候補は追加後に保持し、再検索で再転送しない。上位 K 件だけを返し、総一致件数は別に保持する。
- 不正 UTF-8 / NUL を含む文字列は明示的に拒否する。クエリは 1,024 バイト、
  候補は 65,536 バイト、返却件数は 10,000 件を上限とする。
  ファイル走査側は表示用文字列を scrub し、実際に開くパスは別に保持する。

## FFI と寿命

`core_fuzzy_create` / `add` / `query` / `results` / `destroy` を独立した API 群として追加する。
候補は NUL 区切りの UTF-8 でまとめて追加し、ID は 0 からの追加順とする。
結果は little-endian のバイナリで、先頭に総一致件数 u64 と返却件数 u32、
各レコードに ID u64、スコア i64、一致位置数 u32、位置 u32 配列を格納する。
結果ポインタは次の query / destroy まで有効。Ruby はその場でコピーする。
同じハンドルへの呼び出しは直列化し、close は冪等にする。古いライブラリの関数不足は
他の検索・ZIP API の利用可否に影響させない。

候補ごとの FFI 呼び出しと全件ソートを避け、Zig では最悪候補を根にしたヒープで
上位 K 件を保持する。スコアは O(候補文字数 × クエリ文字数)、作業領域は O(候補文字数)。
一致位置の復元用 O(候補文字数 × クエリ文字数) の領域は上位候補にのみ、一候補ずつ確保する。
スコア計算前に部分列として成立するかを O(候補文字数) で確認し、不一致を早期除外する。

## 実装段階

1. **検索コア**: Zig / Ruby 共通仕様、永続候補、top-K、一致位置、FFI、比較テスト、ベンチマーク。
2. **検索セッション**: 非同期走査、入力の集約、世代番号による古い結果破棄、キャンセル。
   まず単一ワーカーでハンドルを専有し、UI スレッドから destroy しない。
   実測で長い query が問題なら、スコア走査中のキャンセルを追加する。
3. **操作の置き換え**: `s` / `/` を内蔵画面へ、`F` の rga 結果選択も共通画面へ接続する。
   `F` の本文検索には引き続き rga を使う。fzf のヘルスチェックと説明を除去する。
   既存の `fzf_search` アクション名はユーザー設定互換のため別名として維持する。
4. **再表示とプレビュー**: キャッシュを容量・有効期限で制限し、再走査による更新を可能にする。
   新規・削除・外部更新を考慮し、キャッシュ結果が常に最新とは表示しない。
   選択後のプレビューは非同期・サイズ制限付きとし、結果到着で選択 ID が動かないようにする。
5. **展開**: G のファイル名検索と f のフィルターへ適用を検討し、8 プラットフォームをビルド・検証する。

`s` の現行 find は隠しファイルを含む。G の除外拡張子を無条件に流用しない。
ディレクトリのシンボリックリンクは追わず、ファイルリンクの扱いは操作ごとにテストする。
本文検索そのものの高速化と、fzf の検索式全体の互換性は本計画の対象外。

## 検証と計測

- 期待する順位・一致位置、日本語・空文字・重複・同点・追加後の再検索・解放をテストする。
- 同じ候補とクエリで Ruby / Zig の ID・スコア・位置・総件数を一致させる。
- Debug ビルドで安全性を検証し、速度は ReleaseFast で測る。
- 1 万・10 万・100 万候補を用意し、登録時間、検索中央値・p95、返却上限、メモリを測る。
- fzf 比較では同一候補入力を使い、起動・入力転送込みの時間と検索コア時間を区別する。
  初回ディスク走査、入力から描画まで、再表示、プレビューは UI 実装後に別途測る。
- ベンチマークは通常の単体テストから分離し、測定環境・件数・クエリ・試行数を記録する。

## ドキュメントとリリース

各段階の完了状況をこの文書へ追記する。Phase 1 では既存のキー動作と fzf 依存は変えない。
ユーザー操作を切り替える Phase 3 で `help_menu.rb`、info、英日ガイド・README、

## Phase 1 の成果と計測（2026-11-14）

- `lib/rufio/fuzzy_search.rb`: `add` / `query` / `total_matches` / `close`。
  ネイティブ API がない場合と `RUFIO_NATIVE_FUZZY=0` は Ruby にフォールバックする。
  明示的な `native: false` でも Ruby を選択できる。
- `lib_zig/rufio_native/src/fuzzy.zig`: 永続候補、ヒープによる top-K、スコア計算と一致位置復元。
  スレッド共有はまだ行わず、Ruby の Mutex で同一ハンドルの API 呼び出しを直列化する。
- 同梱済みの 1.5.0 バイナリは変更していない。今回のネイティブ検証は `/tmp` 内の
  Debug / ReleaseFast ビルドを使う。通常起動のキー操作は従来どおり。
- 検索の世代管理・キャンセル・ファイル一覧のキャッシュ・プレビューは未実装。
  `add` の保存は一つのインデックスの寿命内だけで、画面を開き直すキャッシュとは異なる。

### 条件

macOS 26.6.2 / arm64、Zig 0.17.0 ReleaseFast、Ruby 4.0.0、fzf 0.74.5。
`test/benchmark_fuzzy_search.rb` で合成パスを生成し、各クエリをウォームアップ後 10 回測定。
4 種類のパス（Ruby ソース・src・日本語ドキュメント・テスト）を交互に生成する。
Zig は登録済み候補から上位 100 件の位置復元と FFI 転送を含む。fzf は `--filter` で
毎回プロセス起動・全候補転送・全結果読み出しを含むため、検索アルゴリズム単体の優劣は示さない。
検索式と順位の完全互換も目標にしていない。ファイル走査・UI 描画・プレビューは含まない。

### 再検索の中央値（ms）

| 候補数 | 実装 | `sctrl` | `src` | `日本` | `xyzmissing` | `a` |
|---:|---|---:|---:|---:|---:|---:|
| 10,000 | Zig | 0.940 | 1.242 | 0.789 | 0.348 | 0.561 |
| 10,000 | Ruby | 51.179 | 52.382 | 24.121 | 13.545 | 33.624 |
| 10,000 | fzf（起動等込み） | 6.734 | 8.391 | 6.528 | 4.290 | 9.235 |
| 100,000 | Zig | 9.041 | 8.460 | 5.569 | 2.859 | 3.939 |
| 100,000 | fzf（起動等込み） | 27.035 | 43.691 | 28.541 | 12.487 | 69.773 |
| 1,000,000 | Zig | 88.159 | 81.002 | 54.118 | 27.008 | 42.007 |
| 1,000,000 | fzf（起動等込み） | 221.312 | 382.845 | 221.829 | 52.905 | 543.563 |

Zig の p95 は、10 万候補で 2.997〜9.329ms、100 万候補で 28.268〜108.487ms。
100 万候補では UI スレッドから直接呼ばず、入力を集約してバックグラウンドで処理する必要がある。
一致しない長いクエリは最初の実装で中央値 309ms だったが、早期除外後に 27ms になった。

### 登録・メモリ

10 万候補の登録は 39.066ms、100 万候補は 404.149ms。1 万候補の最初の測定では
ライブラリロード込みで 497.572ms となり、前回の 5.938ms から大きく変動した。
起動時のロード・ページ初期化等を含む一回の測定なので、登録時間の安定した代表値とはしない。

Zig ワーカーの測定時 RSS は 1 万件 29,760KiB、10 万件 91,872KiB、100 万件 708,896KiB。
Ruby VM・生成元の候補文字列・FFI 用のバッチ等も含むプロセス全体の値で、インデックス単独や
ピーク値ではない。終了済みの fzf 子プロセスの RSS は測っていないためメモリ比較はしない。
100 万候補を無制限にキャッシュする設計にはせず、今後は候補表現の圧縮と容量制限を検討する。

### 再現方法

```sh
zig build-lib lib_zig/rufio_native/src/main.zig -dynamic -lc -O ReleaseFast \
  -femit-bin=/tmp/librufio_fuzzy_release.dylib
RUFIO_FUZZY_BENCH_LIBRARY=/tmp/librufio_fuzzy_release.dylib \
  COUNTS=10000,100000,1000000 REPEATS=10 COMPARE_FZF=1 \
  ruby test/benchmark_fuzzy_search.rb
```

Linux は出力名を `.so` に変更する。fzf の比較が不要なら `COMPARE_FZF` を省略する。
`RUFIO_TEST_FUZZY_LIBRARY` に Debug ビルドを指定して `test/test_fuzzy_search.rb` を実行すると、
Ruby / Zig のランダム比較も必須になる。Zig 単体は `zig build test` または `make test` で実行する。
